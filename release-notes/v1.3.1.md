# v1.3.1 – Bulk Delete Crash Fix & Stale Data Cleanup

**Released:** 2026-03-30

---

## 🐛 Bug Fixes

### Bulk Delete crash: "Cannot read properties of undefined" (Web)

The **Delete ALL Duplicates** bulk delete would crash with:

> `Bulk delete failed: Cannot read properties of undefined (reading 'toLocaleString')`

The server's final SSE "done" event did not include a `current` field, but the JavaScript handler tried to access `data.current.toLocaleString()` on every event before checking the status. Files were still deleted successfully, but the progress modal would error out instead of showing the completion summary.

**Fix:** The "done" status check now runs first, so the completion path never accesses the missing field.

### Stale data after deletion (Web)

After deleting files (individual or bulk), the server-side group data was not updated. This caused:

- Deleted files reappearing when sorting or searching (which re-fetches from server)
- "File not found" errors on subsequent delete attempts
- Exports including already-deleted files

**Fix:** Both `/api/delete` and `/api/scan/<job_id>/delete-all-duplicates` now prune deleted files from server-side groups, summary stats, and raw scan data. The UI summary bar and group list also refresh after deletion.

### Stale data after deletion (Desktop – Windows & macOS)

The desktop app had a similar issue: the in-memory `_groups` list was not cleaned up after deletion. Sorting, exporting, or loading more groups after deleting could reference files that no longer exist.

**Fix:** `self._groups` is now pruned after deletion to remove deleted files and empty groups.
